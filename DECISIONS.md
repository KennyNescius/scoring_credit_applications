# DECISIONS.md — Архитектурные решения

## 1. DTI/PTI расчёт (обязательный алгоритм)

### Почему именно так
- **DTI** = (текущие ежемесячные платежи + платежи по существующим кредитам) / медианный доход
- **PTI** = DTI + платёж по запрашиваемому кредиту / медианный доход
- Используется **медианный** доход (а не средний), т.к. медиана устойчива к выбросам

### Big-O
- O(n) — один проход по existing_loans для агрегации на заявителя
- O(1) — расчёт DTI/PTI для каждой заявки

### Крайние случаи
- Доход = 0 → DTI = 1.0 (максимальный риск)
- Нет существующих кредитов → total_loan_payment = 0
- DTI клиппируется в [0, 5] для предотвращения выбросов

## 2. Cash-flow анализ (обязательный алгоритм)

### Почему именно так
- **CV (Coefficient of Variation)** = std(monthly_income) / mean(monthly_income)
- Стабильный доход (низкий CV) — меньший риск
- Также используем: avg_expense_ratio, avg_naqd_ratio, avg/min balance

### Big-O
- O(m) — один проход по monthly_flows (m = 12 месяцев × n заявителей)
- Агрегация через pandas groupby → O(n·m)

### Крайние случаи
- mean_income = 0 → CV = 0 (fillna)
- Все доходы одинаковы → std = 0, CV = 0 (идеально стабильный)

### Паттерн
- MapReduce: groupby(applicant_id).agg() — каждая группа обрабатывается независимо

## 3. WOE/IV биннинг (бонусный алгоритм)

### Почему именно так
- Квантильный биннинг (5 бинов) через pd.qcut
- WOE = ln(Good% / Bad%) для каждого бина
- IV = Σ (Good% - Bad%) × WOE — мера предиктивной силы фичи
- IV помогает выбрать значимые переменные

### Big-O
- O(n·log(n)) — сортировка для квантилей
- O(k) — расчёт WOE/IV для k бинов (k=5)

### Крайние случаи
- Good% или Bad% = 0 в бине → заменяется на 0.0001
- Менее 5 уникальных значений → duplicates="drop"

## 4. Логистическая регрессия (бонусный алгоритм)

### Почему именно так
- **Интерпретируемость**: каждый коэффициент показывает направление и силу влияния
- class_weight="balanced" — компенсация дисбаланса классов (11.5% дефолтов)
- StandardScaler — нормализация для корректного сравнения коэффициентов
- C=0.5 — умеренная регуляризация для предотвращения переобучения

### Конвертация в скоринговый балл
- Score = Offset + Factor × ln(Odds), где Odds = (1-PD)/PD
- Base Score = 500 при Odds = 19:1 (~5% PD)
- PDO = 50 (каждые 50 баллов удваивают odds)

### Объяснение факторов
- Вклад каждого фактора = -coefficient × (value - baseline) / scale × Factor
- Baseline = среднее значение по train выборке
- Результат в баллах: "+18 за стаж" или "-25 за высокий DTI"

### Big-O
- Обучение: O(n·p·iter) — n заявок, p фичей, iter итераций LBFGS
- Предсказание: O(p) — скалярное произведение

## 5. Binary Search лимита (бонусный алгоритм)

### Почему именно так
- Ищем максимальную сумму кредита, при которой decision = "toladi"
- При увеличении суммы: растёт PTI и summa_daromad_ratio → растёт PD → падает скор
- Монотонная зависимость → применим бинарный поиск

### Big-O
- O(30 × predict) — 30 итераций достаточно для диапазона [100K, 100M]
- predict = O(p) → итого O(30·p)

### Крайние случаи
- Даже минимальная сумма не одобряется → limit = 0
- Максимальная сумма одобряется → limit = max_amount
